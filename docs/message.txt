# INVENTORYPRO
## Warehouse Management System
### FULL-STACK TECHNICAL SPECIFICATION

**Document version:** 1.0.0  
**Project status:** Development Ready  
**Project type:** Full-Stack Web Application  
**Architecture:** REST API / Client-Server  
**Target users:** Warehouse managers, warehouse operators, administrators  
**Frontend:** React, TypeScript  
**Backend:** Node.js, Express.js, TypeScript  
**Database:** PostgreSQL  
**ORM:** Prisma

# PART 01. PROJECT OVERVIEW

## 1.1. Loyiha haqida

InventoryPro — bu kompaniya yoki tashkilotning ombor faoliyatini raqamli boshqarish uchun mo‘ljallangan web-platforma.

Tizim orqali kompaniya:
- Omborlarini boshqarishi.
- Mahsulotlarni ro‘yxatdan o‘tkazishi.
- Mahsulot kategoriyalarini boshqarishi.
- Yetkazib beruvchilarni nazorat qilishi.
- Omborga mahsulot kirimini amalga oshirishi.
- Ombordan mahsulot chiqimini amalga oshirishi.
- Omborlar o‘rtasida mahsulot ko‘chirishi.
- Mahsulot qoldiqlarini real vaqt rejimida kuzatishi.
- Ombor harakatlari tarixini ko‘rishi.
- Kam qolgan mahsulotlar haqida ogohlantirish olishi.
- Hisobotlar va statistikalarni kuzatishi kerak.

## 1.2. Loyihaning asosiy maqsadi

Ombordagi mahsulotlar harakatini qo‘lda yoki Excel orqali boshqarish o‘rniga, barcha jarayonlarni yagona tizim orqali boshqarish.

# PART 02. BUSINESS REQUIREMENTS

## 2.1. Asosiy biznes tushunchalari

### Product

Omborda saqlanadigan mahsulot.

Misollar:
- Laptop.
- Keyboard.
- Mouse.
- Monitor.
- Printer.
- Headphones.

Har bir mahsulot quyidagi xususiyatlarga ega bo‘ladi:

| Field | Type | Description |
|---|---|---|
| id | UUID | Unique identifier |
| name | String | Mahsulot nomi |
| sku | String | Unique product code |
| description | String | Tavsif |
| categoryId | UUID | Kategoriya |
| supplierId | UUID | Asosiy supplier |
| purchasePrice | Decimal | Xarid narxi |
| salePrice | Decimal | Sotuv narxi |
| unit | Enum | O‘lchov birligi |
| minStockLevel | Integer | Minimal qoldiq |
| imageUrl | String? | Mahsulot rasmi |
| isActive | Boolean | Aktiv holati |
| createdAt | DateTime | Yaratilgan vaqt |
| updatedAt | DateTime | Yangilangan vaqt |

**Muhim biznes qoidalari:**

1. Har bir mahsulotning SKU qiymati takrorlanmasligi kerak.
2. Mahsulot nomi majburiy.
3. Narxlar manfiy bo‘lishi mumkin emas.
4. Mahsulot kategoriyasi mavjud bo‘lishi kerak.
5. Ishlatilayotgan mahsulotni oddiy DELETE bilan o‘chirish mumkin emas.
6. Mahsulot ishlatilishdan chiqarilganda `isActive = false` qilinadi.
7. Bir mahsulot bir nechta omborda saqlanishi mumkin.

### Product Units

Mahsulotning o‘lchov birligi quyidagilardan biri bo‘ladi:

- `PIECE` — dona.
- `KG` — kilogramm.
- `LITER` — litr.
- `METER` — metr.
- `BOX` — quti.

MVP davomida mahsulotning o‘lchov birligi yaratilgandan keyin o‘zgartirilmaydi, chunki bu mavjud ombor operatsiyalarini talqin qilishga ta'sir qilishi mumkin.

## 2.5. Stock In — Mahsulot kirimi

Bu modul orqali omborga yangi mahsulot qabul qilinadi.

Misol:

Omborga quyidagi mahsulotlar keldi:

| Product | Quantity | Unit Price |
|---|---:|---:|
| Laptop HP | 10 | 650 |
| Mouse Logitech | 30 | 15 |
| Keyboard | 20 | 25 |

Foydalanuvchi:
1. Omborni tanlaydi.
2. Yetkazib beruvchini tanlaydi.
3. Mahsulotlarni tanlaydi.
4. Har bir mahsulot miqdorini kiritadi.
5. Xarid narxini kiritadi.
6. Izoh qo‘shishi mumkin.
7. Stock In operatsiyasini tasdiqlaydi.

Natija:
- Inventory miqdori oshadi.
- Stock Movement yaratiladi.
- Operatsiya tarixi saqlanadi.
- Dashboard statistikasi yangilanadi.

**Muhim:** Stock In tasdiqlangandan keyin operatsiya oddiy update orqali o‘zgartirilmaydi. Xatolik bo‘lsa, alohida reversal operatsiyasi yoki tuzatuvchi stock movement orqali to‘g‘rilanadi.

## 2.6. Stock Out — Mahsulot chiqimi

Ombordan mahsulot chiqarish jarayoni.

Misol:

| Product | Available | Requested |
|---|---:|---:|
| Laptop HP | 20 | 3 |
| Mouse Logitech | 50 | 10 |

Foydalanuvchi:
1. Omborni tanlaydi.
2. Mahsulotni tanlaydi.
3. Mavjud miqdorni ko‘radi.
4. Chiqim miqdorini kiritadi.
5. Sabab yoki izoh yozadi.
6. Operatsiyani tasdiqlaydi.

Stock Out sabablari:

- `SALE`
- `DAMAGE`
- `INTERNAL_USE`
- `RETURN_TO_SUPPLIER`
- `OTHER`

Biznes qoidalari:

1. Chiqim miqdori 0 dan katta bo‘lishi kerak.
2. Chiqim miqdori mavjud qoldiqdan ko‘p bo‘lishi mumkin emas.
3. Bir vaqtning o‘zida bir nechta foydalanuvchi operatsiya bajarsa ham negative stock yuzaga kelmasligi kerak.
4. Har bir chiqim Stock Movement sifatida saqlanadi.
5. Operatsiyani tasdiqlashdan oldin foydalanuvchi yakuniy ma'lumotlarni ko‘ra olishi kerak.

## 2.7. Stock Transfer — Omborlar o‘rtasida ko‘chirish

Bir ombordagi mahsulotni boshqa omborga o‘tkazish.

Misol:

Tashkent Warehouse → Samarkand Warehouse

| Product | Quantity |
|---|---:|
| Laptop HP | 5 |
| Mouse Logitech | 15 |

Transfer statuslari:

- `PENDING`
- `COMPLETED`
- `CANCELLED`

Jarayon:

1. Source warehouse tanlanadi.
2. Destination warehouse tanlanadi.
3. Mahsulotlar tanlanadi.
4. Miqdorlar kiritiladi.
5. Transfer yaratiladi.
6. Transfer tasdiqlanadi.
7. Source omboridagi miqdor kamayadi.
8. Destination omboridagi miqdor oshadi.
9. Harakat tarixi saqlanadi.

MVP uchun transfer tasdiqlanganda ikki ombor o‘rtasidagi operatsiya bitta database transaction ichida bajariladi.

**Muhim biznes qoidalari:**

- Source va destination bir xil bo‘lishi mumkin emas.
- Mahsulot source omborda yetarli bo‘lishi kerak.
- Transferda bir xil mahsulot bir necha marta takrorlanmasligi kerak.
- Transfer ikkala omborda bir vaqtda aks etishi kerak.
- Bir qismi bajarilib, ikkinchi qismi bajarilmay qolishiga yo‘l qo‘yilmaydi.

## 2.8. Inventory Management

Inventory — har bir mahsulotning har bir ombordagi joriy qoldig‘i.

Masalan:

| Product | Main | Tashkent | Samarkand | Total |
|---|---:|---:|---:|---:|
| Laptop | 20 | 10 | 5 | 35 |
| Mouse | 50 | 25 | 10 | 85 |
| Keyboard | 15 | 30 | 20 | 65 |

Asosiy formula:

`Available Stock = Total Stock In - Total Stock Out + Transfer In - Transfer Out`

Tizim har bir product va warehouse kombinatsiyasi uchun alohida inventory yozuvini saqlaydi.

Inventory statuslari:

- `IN_STOCK` — normal qoldiq.
- `LOW_STOCK` — minimal chegaraga yetgan yoki undan past.
- `OUT_OF_STOCK` — qoldiq 0.

Status avtomatik hisoblanadi.

## 2.9. Low Stock Alerts

Har bir mahsulot uchun `minStockLevel` belgilanadi.

Misol:

- Product: Mouse Logitech.
- Minimum stock: 10.
- Available stock: 7.

Natija: LOW_STOCK.

Agar mavjud miqdor 0 bo‘lsa: OUT_OF_STOCK.

Dashboard va Inventory sahifasida ushbu mahsulotlar alohida ko‘rsatiladi.

## 2.10. Reports & Analytics

Tizim quyidagi hisobotlarni taqdim etishi kerak:

1. Umumiy mahsulotlar soni.
2. Omborlar soni.
3. Umumiy stock quantity.
4. Inventory qiymati.
5. Stock In statistikasi.
6. Stock Out statistikasi.
7. Eng ko‘p harakatlangan mahsulotlar.
8. Kam qolgan mahsulotlar.
9. Omborlar bo‘yicha mahsulotlar taqsimoti.
10. Sana oralig‘i bo‘yicha operatsiyalar.

Hisobotlarda sana oralig‘i bo‘yicha filter bo‘lishi kerak.

Inventory qiymati:

`Inventory Value = SUM(Available Quantity × Average Cost)`

MVP uchun weighted average cost usuli ishlatiladi. Stock In paytida mahsulotning o‘rtacha xarid narxi yangilanadi. Transfer esa mahsulotning umumiy qiymatini o‘zgartirmaydi.

```prisma
enum ProductUnit {
  PIECE
  KG
  LITER
  METER
  BOX
}

  id             String      @id @default(uuid())
  name           String
  sku            String      @unique
  description    String?
  categoryId     String
  supplierId     String?
  purchasePrice  Decimal     @db.Decimal(12, 2)
  salePrice      Decimal     @db.Decimal(12, 2)
  unit           ProductUnit
  minStockLevel  Int         @default(0)
  imageUrl       String?
  isActive       Boolean     @default(true)

}
```

## 6.4. Inventory Model

```prisma
model Inventory {
  id              String   @id @default(uuid())
  productId       String
  warehouseId     String
  quantity        Int      @default(0)
  averageUnitCost Decimal  @default(0) @db.Decimal(12, 2)

  updatedAt       DateTime @updatedAt

  @@unique([productId, warehouseId])
  @@index([warehouseId])
}
```

## 6.5. Stock Movement Model

```prisma
enum MovementType {
  STOCK_IN
  STOCK_OUT
  TRANSFER_IN
  TRANSFER_OUT
  ADJUSTMENT
  REVERSAL
}

model StockMovement {
  id            String       @id @default(uuid())

  warehouseId   String
  type          MovementType
  quantity      Int
  unitCost      Decimal?     @db.Decimal(12, 2)
  referenceType String
  referenceId   String
  createdById   String
  createdAt     DateTime     @default(now())

  @@index([productId, warehouseId])
  @@index([createdAt])
}
```

Laptop HP:

- Samarkand Warehouse: 5 dona.

Operatsiyalar:

1. Main Warehouse'ga 10 dona Stock In.
2. Main Warehouse'dan 5 dona Stock Out.
3. Main Warehouse'dan Samarkand'ga 8 dona Transfer.

Yakuniy natija:

| Warehouse | Initial | In | Out | Transfer | Final |
|---|---:|---:|---:|---:|---:|
| Main | 20 | +10 | -5 | -8 | 17 |
| Samarkand | 5 | 0 | 0 | +8 | 13 |

Umumiy stock:

`17 + 13 = 30`

Boshlang‘ich 25 dona + 10 dona kirim − 5 dona chiqim = 30 dona.
